Group 4 — the canonical re-emit loop + opt-in data-node-id

S4.1 — OPT-IN threading: every emitted element carries data:node-id

every emitted element has a data:node-id prop whose value is a real nodeById key; the ops stream carries the data: prop; the DOM adapter sets the attribute.

S4.2 — DEFAULT OFF: no data:node-id anywhere; byte-identical

no data:node-id on any element; the emitted element set is identical to the opted-in run modulo the data:node-id props alone.

S4.3 — prevMap chain: re-render after mutation keeps stamping

first render with options stamps every element; dispatch click + re-render with caller-held prevMap is incremental (set-only, no re-creates) and stamps persist; third no-change render yields zero ops.

S4.4 — destroy-prune under the option: destroyed wire removed, never re-created

re-render after destroy does NOT re-create the destroyed element (remove only); surviving elements keep data:node-id.
