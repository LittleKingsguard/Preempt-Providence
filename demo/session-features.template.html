Landed-features scenarios — css.classes seam, retained-handler-map listener lifecycle, Supervisor.dispatchEvent (Phase A). See docs/specs/landed-features-scenarios.md.

Group 1 — css.classes injection seam

S1.1 — provider-colored badge (scalar append)

class attribute = badge is-primary (host class first, injected appended); translate emits no gap warning for the seam target.

S1.2 — array-form multi-class injection (in order)

class attribute = badge is-primary is-large (array order preserved, host-first).

S1.3 — missing/unresolved source keeps the authored list

element still renders with class badge ONLY (nothing wiped); unresolved-reference compile fail-state; no throw anywhere.

S1.4 — blocked css targets warn + skip, never throw

translate emits component-target-skipped for exactly the four blocked targets (css, css.id, css.style, css.style.color); no component-target-gap; the button's own authored css stays intact.

S1.5 — reverse round-trip: target css.classes persists warning-free

re-translated tree is warning-free (no new gap warn, no double-emit); the reversed doc renders the same badge is-primary class plan.

Group 2 — retained-handler-map listener lifecycle

S2.1 — a handler that removes its own binding really detaches

first click writes clicked and clears the compiled handlers; the diff emits set('on:click', undefined); the retained listener is removed; a second click runs nothing and content is preserved.

S2.2 — element removal purges the retained listener

dispatching the remove-trigger destroys remove-me: its element is gone, its retained listener is purged, and the page still renders without the control.

Group 3 — Supervisor.dispatchEvent engine entry

S3.1 — drive a data-authored control through the ENGINE entry (not onEvent)

dispatchEvent(id, 'click', 'hi') runs the body with event.value === 'hi'; the re-rendered button text is hi!; results [undefined].

S3.2 — fork-arm wire target fires the node once with all arms in ctx.states

2 fork arms resolved; dispatchEvent(display#0, 'click') fires exactly once, results [1], and the recorded ctx.states length is 2 (arms prop = "2").

S3.3 — unknown and destroyed targets are safe no-ops

dispatchEvent('no-such-id') → []; after destroying the victim, dispatchEvent(destroyedId) → []; the page never throws and stays alive.

S3.4 — dispatch is a trigger: a READ-ONLY dispatch re-renders nothing

a read-only dispatch produces no pass-2 states and no re-render; a subsequent apply DOES re-render.

S3.5 — no propagation: only the target's handlers fire

dispatching the child fires ONLY the child handler (results [1]); the panel handler stays silent and its content is unchanged.

S3.6 — same-(node,event) reentrancy no-ops; a different event fires

a self-re-dispatching click runs exactly once (nestedLen prop = "0"); dispatching 'focus' still runs FocusCapture (focus prop = "1", results ["focus"]).
