Loop-safety probes

Mirror of tests/e2e/loop-safety.test.ts — intentionally tries to create infinite circles through the public surface and asserts the safety guard trips. Each probe shows its expected behavior, the graph structure built, and the observed result.

Probe 1 — A→B→A anchors: attach/move that would close the circle

Expected: move a under b (where the tree is root → a → b) is rejected with cycle-detected; the graph is rolled back and nothing is journaled. 


      

    


    

      
Probe 2 — A↔B anchor circle compile

      

        Expected: compiling a graph where a and b are each other's parent yields zero
        actionable states, a dropped loop arm, and a
        circular-source warning — bounded, never hangs.
      

      

      

    


    

      
Probe 3 — component self-reference

      

        Expected: a node that both provides and consumes self-slot resolves at
        depth 0 (S4.1/S-R2.6) with status ok — it is not a loop.
      

      

    


    

      
Probe 4 — dangling source/target (unresolved reference)

      

        Expected: a target with no source anywhere logs a warning, emits status
        unresolved-reference, and the node still renders its own state (S-R4.3).
      

      

    


    

      
Probe 5 — prototype-only candidate drops silently

      

        Expected: when the only provider lives under a component prototype, the arm
        terminates at component and drops silently — zero events, zero
        warnings.
      

      

    


    

      
Probe 6 — deep acyclic chain

      

        Expected: a borrow walk far deeper than MAX_COMPILE_DEPTH = 8 compiles
        actionable — parent-chain classification is memoized and cycle-only
        (compile-horizon §6.1), so depth is not a loop signal for an acyclic chain. Only a
        genuine revisit (a real cycle) drops as loop with a
        circular-source warning.
      

      

      

    


    

      
Probe 7 — single-parent enforcement

      

        Expected: a second parent is rejected with SingleParentError — never a
        silent reparent.
