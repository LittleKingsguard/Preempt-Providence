Preempt-Providence — e2e mirror demos

Browser mirrors of the Step 7 e2e suites. Each page runs the exact scenarios from its vitest twin against the same compiled core and renders the tested data (trees, fork arms, warnings, guard trips) as visible content with live PASS/FAIL results.

Demos

  • SSR receive → complete render — mirrors tests/e2e/ssr-render.test.ts. The page is generated by scripts/build-demo.mjs: the e2e input data is serialized by the framework into the preempt-initial-data document and embedded in the HTML, then re-resolved and rendered in-browser. Shows expected behavior, the expected document tree structure, the live rendered DOM, fork arms, and PAR-5 parity vs the embedded server reference.
  • Loop-safety probes — mirrors tests/e2e/loop-safety.test.ts: A→B→A circles, component self-reference, dangling source/target, deep acyclic chains (compile actionable — depth is not a loop signal), single-parent enforcement — each with its expected behavior, the graph structure built, and the observed guard trip.
  • Component-driven rendering (bonus) — the only hand-written HTML is the skeleton and the #root placeholder; everything else is framework-rendered. Nodes carry target component references for type/children (populating descendants) and source references for the values in those children; every element shows the placement/component resolution it follows, and each test is a content node in the tree. Includes a working user pane: a component-provided after-compile handler populates it from session state — click Log in (mock login showing the predefined user) or Log out.
  • Mode toggle — SSR / client / markdown adapters — the same feature-matrix document rendered through three adapter modes (toggle bar). SSR: the server sends the full <app>…</app> HTML it rendered through the real SSRFragmentAdapter — inspect it in the devtools Response tab, then compare with the raw received string and the parsed mount on the page. Client: the browser re-resolves the serialized document (S4.2) with no server payload. Markdown: the raw editor source is embedded verbatim for manual inspection alongside the live parsed display. Every mode runs the identical shared feature-matrix checks plus its mode-specific ones. Served dynamically per ?mode= by scripts/serve-demo.mjs.
  • Fork stress — layered child-creation stress test (d2 · d4 · d6 · d8 · d9 · d10 · d11 · d12) — a demo-only stress test of the forking render system. A binary tree is built layer by layer, each layer adding 2 children per node through one of the four runtime child-creation mechanisms, cycling: placement → component values → component link → idempotent handler → repeats with different placement/component names. Depth dN has 2N − 1 nodes (d12 = 4095 nodes; the memoized, cycle-only parent-chain classifier keeps every layer actionable). Every node renders its stress:layers chain (depth + tree-back-to-root). The page uses ONLY core (dist/core/*) and handler code — no demo-side render machinery.
  • Fork stress (data-driven) — prototype-driven assembly from a legacy envelope (d2 · d4 · d6 · d8 · d9 · d10 · d11 · d12) — the same deep binary stress tree (2N − 1 nodes, d12 = 4095), assembled from a LEGACY envelope alone: preempt-initial-data carries the legacy format (root + two prototype nodes per layer — one per sibling slot) which translateLegacy parses. Each prototype declares its stress-expand after-compile handler by NAME in the data (bodies can't be JSON-serialized); the page supplies the body and recursion does the rest: cloning the layer-1 prototypes onto the root, each clone's inherited handler expanding the next layer via the clone-instance op until depth N. CORE ONLY — no demo-fixtures, no demo-side render machinery; the shared levelCss/cssPropForLevel helpers are pure data-derivation (demo-only, not core APIs).

Run

npm run demo        # builds dist/core + generates demo/ssr-render.html, demo/components.html,
                    # demo/feature-matrix.html & demo/mode-toggle.html, then serves
                    # http://localhost:4173/demo/
npm run demo:smoke   # headless: runs all pages' checks against a DOM shim, asserts all pass
